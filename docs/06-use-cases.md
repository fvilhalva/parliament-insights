## UC01 — Query a structural metric by year

- **Primary actor:** Analyst/Evaluator
- **Precondition:** thesis artifacts already ingested (FR09).
- **Main flow:**
  1. User submits a natural-language question (e.g. *"what was the modularity in 2024?"*).
  2. The agent classifies the intent as a structured query (FR05).
  3. The Structured Query Tool extracts parameters (year, metric) and runs a parameterized query.
  4. The result is formatted in natural language and returned with the **exact value**.
- **Alternative flow:** metric/year not found → explicit *"data not available"*, no inference.
- **Postcondition:** correct response, traceable to the source `analysis_{year}.json`.

## UC02 — Search propositions by semantic similarity

- **Primary actor:** Analyst/Evaluator
- **Precondition:** embeddings of proposition summaries already generated (FR10).
- **Main flow:**
  1. User asks a thematic question (e.g. *"which environmental proposals did community 3 co-author in 2025?"*).
  2. The agent identifies semantic-search intent and extracts filters (community, year).
  3. The RAG Tool embeds the question and runs a similarity search (pgvector) with a metadata filter.
  4. Retrieved context is sent to the LLM, which answers **citing the source propositions** (FR06).
- **Postcondition:** response with explicit citation of the `proposition_id`s used.

## UC03 — Get a thematic community summary

- **Primary actor:** Researcher
- **Main flow:**
  1. An asynchronous batch process collects summaries of all propositions co-authored by a Louvain community.
  2. The LLM generates a thematic summary of the set.
  3. The summary is stored in a cache (`CommunitySummary`).
  4. The API exposes the ready-made summary on demand, with **no new LLM call** (FR07).
- **Constraint:** the summary is explicitly labeled an *exploratory tool*, not part of the thesis's statistical validation.

## Main flows (sequence, textual)

**Flow 1 — Structured Query (UC01)**
```
Client → API(NestJS): POST /query {question}
API → Agent: invoke(question)
Agent: parse_intent() → {year, metric}
Agent → Structured Query Tool → PostgreSQL: SELECT ... WHERE year=%s
PostgreSQL → Tool: rows (validated data)
Tool → Agent → API: natural-language response   [no numeric value generated by LLM]
API → Client: 200 OK {answer, source, generated_by_llm:false}
```

**Flow 2 — RAG Search (UC02)**
```
Client → API: POST /rag-query
API → Agent: invoke(question)
Agent → RAG Tool: embed_query()
RAG Tool → pgvector: similarity_search(top-k, community filter)
pgvector → RAG Tool: relevant propositions
RAG Tool → LLM: build_prompt(context) → generate()
LLM → RAG Tool: generated answer
API → Client: 200 OK {answer, sources[]}
```

**Flow 3 — Batch Summarization (UC03)**
```
Scheduler → Queue(Redis): enqueue(job: community X, year Y)
Worker → Queue: consume(job)
Worker → PostgreSQL: fetch summaries for community
Worker → LLM(Ollama): summarize(text) → thematic summary
Worker → PostgreSQL: INSERT CommunitySummary (cache)
[API later serves the cached summary with no new LLM call]
```
